两种实现策略（编译期可选）：

| 策略 | 说明 | 优点 | 缺点 |
|------|------|------|------|
| **A. libmodbus** | 使用开源 libmodbus 库 | 成熟稳定、RTU+TCP 都支持 | 多一个依赖 |
| **B. 手写** | 自己实现 Modbus RTU 帧解析 | 零依赖、深入理解协议 | 工作量大 |

**建议选 A（libmodbus），面试官更认可"会选型"而非"全部自己造轮子"。**

Modbus 配置结构：

```c
// 在 common.h 中新增
#define MODBUS_DEVICE_MAX  8      // 最多接入 8 个 Modbus 从设备
#define MODBUS_REG_MAX     32     // 每个设备最多 32 个寄存器映射

struct modbus_reg_map {
    int     slave_id;             // 从站地址 (1-247)
    int     reg_addr;             // 寄存器起始地址 (30001, 40001 等)
    int     reg_count;            // 连续寄存器数量
    int     func_code;            // 功能码 03(读保持寄存器) 04(读输入寄存器)
    char    data_type[16];        // int16 / uint16 / float32 / int32
    char    field_name[32];       // 映射到 sensor_data 的哪个字段
    double  scale;                // 比例因子（原始值 × scale = 物理值）
    double  offset;               // 偏移量
};

struct modbus_config {
    int     enabled;
    char    mode[8];              // "rtu" 或 "tcp"
    // RTU 参数
    char    serial_port[64];      // /dev/ttyUSB0
    int     baudrate;             // 9600, 19200, 38400, 115200
    char    parity[2];            // N, E, O
    int     data_bits;
    int     stop_bits;
    // TCP 参数
    char    tcp_host[128];
    int     tcp_port;             // 默认 502
    // 寄存器映射
    int     poll_interval_ms;     // 轮询间隔
    int     reg_count;            // 实际配置的寄存器映射数量
    struct  modbus_reg_map regs[MODBUS_REG_MAX];
};
```

#### 2.2 Modbus 轮询线程

- `modbus_master_init()`：初始化 RTU（`modbus_new_rtu`）或 TCP（`modbus_new_tcp`）上下文，连接所有从站
- `modbus_poll()`：按 `poll_interval_ms` 周期轮询，读取寄存器值 → 应用 scale/offset 转换 → 填充 `sensor_data` 结构
- 与 `sample_thread` 合并或作为独立线程，采集到的数据统一走 `mqtt_publish()` 或 `storage_save()`
- **模拟模式**：当 Modbus 硬件不可用时，自动回退到模拟数据（与 sensor mock 一致）

#### 2.3 Modbus Slave 模拟器（开发调试用）

无需硬件即可验证：
- 安装 `pymodbus`：`pip install pymodbus`
- 提供的 Python 脚本启动一个 TCP Modbus Slave（`modbus-slave-sim.py`）
- 模拟 PLC 数据：寄存器 40001=温度×10, 40002=湿度×10, 40003=转速

规则配置格式（在 `node.conf` 中）：

```ini
# 规则定义：每条规则一行
# 格式: rule_N = field,operator,threshold,action
# operator: gt(>), lt(<), eq(==), ne(!=), between(区间), rate(变化率)
# action:   alert_mqtt, gpio_1, gpio_2, log_only, all

rule_1 = temperature,gt,85.0,alert_mqtt+gpio_1     # 温度 >85℃ → MQTT报警+GPIO1
rule_2 = humidity,lt,10.0,alert_mqtt                # 湿度 <10%  → MQTT报警
rule_3 = pressure,between,950.0_1050.0,log_only     # 气压在950-1050范围外→仅日志
rule_4 = temperature,rate,5.0_60s,alert_mqtt+gpio_1 # 温度1分钟内上升>5℃→报警
```

C 代码核心结构：

```c
// 运算符枚举
enum rule_op { OP_GT, OP_LT, OP_EQ, OP_NE, OP_BETWEEN, OP_RATE };

// 动作位掩码
#define ACTION_LOG_ONLY   0x01
#define ACTION_ALERT_MQTT 0x02
#define ACTION_GPIO_1     0x04
#define ACTION_GPIO_2     0x08

// 规则结构体
struct rule {
    char        name[32];
    char        field[32];          // temperature, humidity, pressure
    enum rule_op op;
    double      threshold;          // 单阈值
    double      threshold_lo;       // between 下界
    double      threshold_hi;       // between 上界
    double      rate_window_s;      // rate 操作的滑动窗口（秒）
    uint8_t     action_mask;        // 触发时执行的动作
    int         cooldown_ms;        // 冷却时间（防止重复告警）
    int64_t     last_triggered;     // 上次触发时间戳
};
```

#### 3.2 规则引擎核心函数

```c
// 初始化：从配置文件加载所有规则
int rule_engine_init(const char *config_path);

// 评估：对一条传感器数据评估所有规则，返回触发的动作掩码
uint8_t rule_engine_evaluate(const struct sensor_data *data);

// 评估单个规则
static int rule_match(const struct rule *r, const struct sensor_data *data);

// 销毁
void rule_engine_close(void);
```

- 变化率（`rate`）操作需要用环形缓冲区记录历史值和时间戳
- 冷却时间（`cooldown_ms`）防止同一告警反复触发

#### 3.3 GPIO 告警动作

- 调用 `gpio_hal_set(pin, value)` 控制 GPIO 引脚输出高/低电平
- 控制继电器模块（GPIO → 继电器 → 声光报警器/风扇/阀门）
- 在模拟模式下，GPIO 操作降级为 `LOG_INFO("GPIO%d would be SET to %d", pin, value)`

#### 4.2 A/B 分区实现

在 x86-64 开发阶段用两个目录模拟：

```
/tmp/embmqttnode/
├── slot_a/           ← 当前运行版本
│   └── embmqttnode
├── slot_b/           ← 备用版本（升级目标）
├── current_slot      ← 文本文件，内容 "A" 或 "B"
└── download/         ← 固件下载临时目录
```

核心数据结构：

```c
#define OTA_SLOT_A    0
#define OTA_SLOT_B    1
#define OTA_STATE_IDLE         0
#define OTA_STATE_DOWNLOADING  1
#define OTA_STATE_VERIFYING    2
#define OTA_STATE_INSTALLING   3
#define OTA_STATE_REBOOTING    4

struct ota_context {
    int     state;                      // 当前状态
    int     active_slot;                // 当前运行的槽位 (A=0, B=1)
    int     target_slot;                // 升级目标槽位
    char    current_version[32];        // 当前固件版本
    char    target_version[32];         // 目标固件版本
    char    download_url[256];
    char    expected_checksum[128];     // SHA256 校验值
    char    firmware_path[256];         // 下载的固件文件路径
    int     download_progress;          // 0-100
    int     boot_attempt;              // 启动尝试次数（防反复重启）
};
```

#### 4.3 升级流程实现

```
ota_check_and_handle() 在 main 循环中每 10 秒调用一次：

1. 检查 MQTT 是否收到 ota/cmd 消息
2. 收到 upgrade 指令 → 进入 DOWNLOADING 状态
3. ota_download(url) → 用 libcurl 或手写 HTTP GET 下载固件包
4. ota_verify(path, checksum) → SHA256 校验 + Ed25519 签名验证
5. ota_install(path, target_slot) → 解压到备用槽位
6. ota_set_boot_slot(target_slot) → 修改启动标志
7. ota_reboot() → system("reboot") 或 exit(42) 由 systemd 自动重启
8. 启动后 ota_post_boot_check() → 如果新版本 3 次启动失败 → 自动回滚
```

#### 4.4 配套工具脚本

```
新增文件: tools/ota_gen_firmware.sh
```

```bash
#!/bin/bash
# 打包固件：编译 → 生成版本文件 → tar.gz → SHA256 → Ed25519 签名

VERSION=${1:-"1.0.0"}
make CROSS_COMPILE=aarch64-linux-gnu-
mkdir -p dist/embmqttnode_${VERSION}
cp bin/embmqttnode dist/embmqttnode_${VERSION}/
echo "$VERSION" > dist/embmqttnode_${VERSION}/VERSION
cd dist && tar czf embmqttnode_${VERSION}.tar.gz embmqttnode_${VERSION}/
sha256sum embmqttnode_${VERSION}.tar.gz > embmqttnode_${VERSION}.tar.gz.sha256
echo "Firmware: dist/embmqttnode_${VERSION}.tar.gz"
echo "SHA256:   $(cat dist/embmqttnode_${VERSION}.tar.gz.sha256)"
```

#### 4.5 安全考量

- **固件签名**：使用 Ed25519 签名（libsodium 提供，体积小），防止固件被篡改
- **HTTPS 下载**：OTA 固件 URL 支持 HTTPS，防止中间人攻击
- **回滚保护**：即使签名校验失败也能滚回旧版本，不会变砖
- **启动计数**：systemd 的 `StartLimitBurst` + OTA 自身启动尝试计数双重保护

```yaml
          - target: armhf
            cross_compile: arm-linux-gnueabihf-
            os: ubuntu-22.04
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/checkout@v4
      - name: Install deps
        run: |
          sudo apt update
          sudo apt install -y build-essential libmosquitto-dev libsqlite3-dev
          if [ "${{ matrix.cross_compile }}" != "" ]; then
            sudo apt install -y crossbuild-essential-${{ matrix.target }}
          fi
      - name: Build
        run: make -C src CROSS_COMPILE=${{ matrix.cross_compile }}
      - name: Test (x86_64 only)
        if: matrix.target == 'x86_64'
        run: make -C tests test
```
