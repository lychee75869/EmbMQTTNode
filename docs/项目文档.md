## 项目总览

| 项 | 值 |
|---|---|
| 一句话定位 | 一台跑在 ARM64 Linux 单板上的**工业边缘网关**：南向以 Modbus 主站采集子设备，北向以 MQTT over TLS 接入华为云 IoTDA，本地附带 HTTP Dashboard。 |
| 形态 | C11 单进程多线程；零框架、零 GC、零动态 schema |
| 硬件平台 | Orange Pi Zero 2W（全志 H618，四核 Cortex-A53，4GB RAM），Ubuntu 24.04 |
| 南向 | Modbus RTU/TCP（libmodbus，主站） |
| 北向 | MQTT + TLS（libmosquitto，8883），华为云 IoTDA；可切换回本地 mosquitto |
| 本地 | SQLite 断网续传；HTTP Dashboard（REST + 单页前端）；A/B 分区 OTA |
| 构建 | GNU Make，支持 `aarch64-linux-gnu-` 交叉编译；WSL 亦可本地构建与测试 |
| 代码规模 | 约 27 个源文件（15 个 `.c` + 12 个 `.h`）；11 个单元测试二进制 |
| 外部依赖 | libmosquitto、libsqlite3、libmodbus（可编译期关闭）、OpenSSL（`-lcrypto`/`-lssl`）——**零新增框架** |
| 版本线 | v0.x（单传感器节点）→ v1.x（边缘网关）→ v1.3.0（华为云接入）→ v1.4.0/v1.5.0（纯网关化，移除本地采集/GPIO/ML 引擎）→ **v1.5.1** |

### 面试叙事主线

> 「我把一台便宜的 ARM 开发板做成了一台**可靠的工业边缘网关**：南边用 Modbus 把车间/农业里的存量设备采上来，北边用 TLS+MQTT 接到华为云；过程中最考验工程能力的是**断网不能丢数据**、**固件能安全地远程升级**、**协议差异被干净地隔离在平台层**，以及**云端命令下发/回执/OTA 全链路的可靠性**。本地采集、GPIO 执行、端侧 ML 这些职责后来被我主动**下移**到子设备和视觉侧——网关只做它最该做的事：协议转换、云端接入、数据不丢。」

一句话概括技术亮点：**表驱动的子设备映射 + 平台抽象层（call site 零分支）+ 断网续传 + 签名 fail-closed 的 A/B OTA + 华为云命令闭环**。

## 模块一 · 子设备（从站侧）

> 子设备 = 现场被采集的对象。当前以一块 STM32 农业执行端（温湿度/土壤/水位/电池 + 水泵执行）为原型，通过 Modbus RTU/TCP 挂在网关南向。

### 1. 数据契约：子设备寄存器布局

**职责**：约定网关与子设备之间的唯一接口——一段固定地址的保持寄存器。

**关键设计与理由**：

- **保持寄存器（Holding Register）+ 功能码 03（读）/ 06·16（写）**：值可读可写，语义最贴近"设备状态 + 执行设定"，兼容绝大多数 PLC/仪表。
- **地址 40001-40008 一张表说清**，读写都在同一窗口，子设备固件与网关配置共用此契约。
- **数值一律定点缩放（÷10 / ÷100）存整数**：Modbus 寄存器是 16 位，浮点需跨寄存器拼接易错；定点整数换算简单、字节序无歧义。
- **方向显式标注**：读=传感器量测，写=执行器设定，网关据此决定轮询（03）与写命令（06/16）。

| 地址 | 名称 | 方向 | 类型 / 换算 | 单位 | 说明 |
|---|---|---|---|---|---|
| 40001 | 土壤湿度 | 读 | uint16 ÷ 10 | % | 0-100 |
| 40002 | 空气温度 | 读 | int16 ÷ 10 | ℃ | 可负 |
| 40003 | 空气湿度 | 读 | uint16 ÷ 10 | %RH | 0-100 |
| 40004 | 水槽水位 | 读 | uint16 ÷ 10 | % | 0-100 |
| 40005 | 电池电压 | 读 | uint16 ÷ 100 | V | 例如 1260 → 12.60V |
| 40006 | 浇水秒数 | 读写 | uint16 | s | 执行器设定 |
| 40007 | 泵速 | 读写 | uint16 | % | 执行器设定 |
| 40008 | 状态字 | 读 | uint16 位域 | — | 见下 |

状态字（40008）位域：

| 位 | 含义 |
|---|---|
| bit0 | 水泵运行中 |
| bit1 | 水槽缺水 |
| bit2 | 土壤湿度传感器故障 |
| bit3 | 电池低电量 |
| bit4 | 自动模式使能 |
| bit5-15 | 保留 |

**被否决的方案**：用多个功能码分散在输入寄存器/线圈（04/01/02）——读写窗口割裂、子设备固件与网关都要维护多套地址，收益为零。

**验证方式**：`tests/test_modbus_config.c`（配置解析与寄存器映射）；真机/模拟器轮询目视核对（`tools` 下 Modbus slave 模拟器）。

**后续**：见本文档「模块一 · 4 待开发：STM32 执行端固件」——该契约的**从站实现**尚未上板。

### 2. 网关侧子设备映射（`subdev_registry.c/h`）

**职责**：把「子设备 device_id ↔ 数据源」的映射做成一张**数据源无关**的配置表。

**关键设计与理由**：

- **表驱动 + 数据源无关**：查表键是"数据源键"（modbus 用 `slave_id`；预留 sensor 用 `sensor_type`），网关核心代码不感知具体驱动。未来换子设备/加协议只改配置，不改代码（演进期核心零改动）。
- **INI 风格子配置 `subdevices.conf`**：与 `node.conf` 解析风格完全一致（`key = value`，`#`/`;` 注释，`[段]` 跳过），运维认知成本为零。
- **fail-closed 校验**：非法条目**整条丢弃 + WARN**，不影响其它条目——一条写错不会拖垮整表。
- **唯一性约束**：`device_id` 全表唯一、`(data_source, source_key)` 全表唯一，避免路由歧义。

格式：

```ini
# subdevice_N = <data_source>,<source_key>,<device_id>,<name>[,<service_id>]
#   data_source: modbus | sensor（预留 ble）
#   source_key : modbus→slave_id(1-247)；sensor→sensor_type
#   service_id : 可选，缺省 SensorData（须与云侧产品模型对齐）
subdevice_1 = modbus,1,e5f6a7b8-zzzz,PLC-Line1
```

校验规则（`fail-closed`，非法整条丢弃 + WARN）：

| 规则 | 处置 |
|---|---|
| 条数 > `SUBDEVICE_MAX`(16) | 超出丢弃 |
| `data_source` 非 `modbus`/`sensor` | 丢弃（预留枚举位，不报错） |
| modbus: `slave_id` 非 1..247 | 丢弃 |
| `device_id` 空 / 超 256 / 含空格或 `$ # +`（MQTT 通配符） | 丢弃 |
| `device_id` 重复、`(data_source,source_key)` 重复 | 丢弃 |
| `service_id` 含非法字符 | 回落缺省 `SensorData` |
| 文件不存在 / 0 条 | WARN + 空表（纯网关模式，不 crash） |

**被否决的方案**：把映射硬编码进 C 代码 / 用动态 key-value 表——前者改设备要重编译，后者牺牲类型安全（见模块二 · 2）。

**验证方式**：`tests/test_subdev_registry.c`（合法/越界/重复/通配符/空文件/256 长度 device_id 全覆盖）。

**后续**：无（该线已闭环；新增数据源只需加枚举位与 source_key 解析）。

### 3. 云侧子设备注册与上下线

**职责**：让每个子设备在华为云 IoTDA 上**呈现为独立设备**，并如实反映其在线状态。

**关键设计与理由**：

- **网关代子设备注册**：调 `.../gateway/sub_devices/register`，收到 response 后子设备成为平台上的独立设备（设备树可视化）。
- **上下线状态上报**：`.../gateway/sub_devices/status` 上报 `ONLINE/OFFLINE`；离线由「超时无数据」判定（`subdev_offline_sec`）。
- **批量属性上报**：`.../gateway/sub_devices/properties/report`，`{"devices":[{...}]}` 结构，单条 ≤1MB。

> 实现文件 `platform_huawei_subdev.c` 归**模块三 · 2（云端）**，此处仅声明职责归属；细节见该节。

**验证方式**：平台设备树可见性 + 状态实时性（真机项，见模块三 · 5）。

### 4. 待开发：STM32 执行端固件

**职责**：把上表寄存器契约在 STM32 侧实现为 Modbus RTU 从站，并具备本地兜底自动浇水。

**关键设计与理由**：

- **F103 移植 + Modbus RTU slave**：实现功能码 03/06/16，维护寄存器映像；网关轮询与写命令即可闭环。
- **本地湿度兜底自动浇水**：**断网/网关离线时子设备仍能自主按土壤湿度阈值浇水**——把"安全底线"下沉到最靠近执行器的一端，不依赖网络与云端（这是"边缘"的本质）。
- **与网关的边界清晰**：网关负责采集与云端接入；子设备负责执行与离线兜底，二者只通过寄存器契约耦合。

**被否决的方案**：把执行逻辑留在网关（云端下发才浇水）——断网即失效，安全底线不应依赖网络。

**验证方式**：待固件齐备后，用 Modbus 模拟器 + 真机双向验证（读 5 路量测、写浇水秒数/泵速、断网兜底）。

## 模块二 · 网关（南向 + 数据面 + 北向）

> 网关是"协议转换 + 云端接入 + 数据可靠"的中枢。南向是 Modbus **主站**，子设备是**从站**。

### 1. 南向通信：Modbus 主站（`modbus_master.c/h`）

**职责**：周期轮询各从站、按配置把寄存器映射成网关数据字段，产出统一的 `sensor_data`。

**关键设计与理由**：

- **网关是主站**：主动发起 03 读；子设备被动响应。轮询周期 `poll_interval_ms` 可配。
- **RTU/TCP 双模式**：`mode = rtu | tcp`，RTU 参数（串口/波特率/校验/数据位停止位）/TCP 参数（host/port 502）分别配置；一套代码适配现场与仿真。
- **寄存器映射表驱动**：每条 `modbus_reg_N` 描述 `slave_id / 起始地址 / 功能码 / 数据类型 / 字段名 / scale / offset`，**采上来的原始值经 scale/offset 换算后落到字段**，采集逻辑与协议细节解耦。
- **输入校验前置（fail-closed）**：配置解析期即做范围校验（如 `slave_id` 1-247、地址合法），并对 libmodbus 调用做防御性复查。
- **mock 降级**：`BUILD_WITH_MODBUS=0` 时走 mock 数据路径，保证无硬件/无库环境下仍可构建与回归。

**被否决的方案**：手写 Modbus 帧解析——工作量大且易错；选用成熟 libmodbus 体现"会选型"而非"全部自己造"。

**验证方式**：`tests/test_modbus_config.c`（配置解析 + mock 路径）；双编译路径（`BUILD_WITH_MODBUS=0/1`）零警告。

**后续**：无（ST 子设备上板后即为真机联调，见模块一 · 4）。

### 2. 数据模型与字段描述表

**职责**：定义网关内部统一的数据结构，并把「字段名 ↔ 值」映射收敛为**单一事实源**。

**关键设计与理由**：

- **`struct sensor_data` 是唯一数据载体**：含量测字段 + `timestamp_ms`（采样时刻）+ `source`/`source_id`（数据来源标识）。
- **无效值哨兵统一为 `SENSOR_VALUE_INVALID (-999.0)`**：历史上 SHT30 用 `-1.0`、Modbus/引擎用 `-999.0`，导致"无此字段"被判成真实量测参与告警（隐藏 bug）。统一为一个宏后，哨兵赋值点与判定点全部引用同一常量。
- **字段描述表 `sensor_fields.c/h`（单一事实源）**：`const struct sensor_field SENSOR_FIELDS[]`（`name` / `offsetof` / `type`）+ `sensor_get_field`/`sensor_set_field`/`for_each_field`。**序列化、取值、上报、Dashboard 全部查表/遍历，禁止各写 strcmp 链**。
- **新增字段退化为固定 4 步**：改 `struct` 加 1 成员、表尾追加 1 行、生产侧采集、`storage` 加 1 列——**消费侧零改动**。
- **表序 = 序列化字段序 = 原 payload 序（冻结不变式）**：保证 local 路径输出逐字节不变。

**被否决的方案**：动态 key-value / EAV / JSON blob 通用属性 map——破坏类型安全、引入堆分配、查表从 O(1) 退化为线性、`storage` 固定列语义丢失；字段数为个位数，具名 struct + 一张描述表是甜点区。

**验证方式**：`tests/test_sensor_fields.c`（表序 / 存取 / 黄金 payload 逐字节对比）。

**后续**：无。

### 3. 北向通信：MQTT + TLS 客户端（`mqtt_client.c/h`）

**职责**：维护到 broker/云平台的唯一传输连接，发布数据/状态/告警，接收下行消息。

**关键设计与理由**：

- **连接参数由平台层提供**：`mqtt_init` 经 `platform_connect_params` 取 client_id/username/password/keepalive/遗嘱/TLS 落点；传输层不关心平台差异（见模块二 · 6）。
- **TLS 落点由 `force_tls` 驱动**：华为模式恒强制 8883+TLS，不依赖用户在 `node.conf` 额外配 `tls_enabled`（fail-closed，杜绝明文连接）。
- **遗嘱消息（Last Will）**：本地路径用 broker 遗嘱兜底离线状态；华为模式不发遗嘱（平台自动维护在线状态）。
- **重连即重订阅**：`clean_session` 下 broker 断连会清空订阅，故**每次 CONNACK 成功都重订主题**并重发 online（否则 OTA/命令通道在重连后静默失效——这是曾经的线上缺陷）。
- **断连去重（非阻塞-12 修复）**：CONNACK 失败与真实断连是**两个**触发点，用「会话曾建立」旗标 + 原子交换保证 `platform_on_disconnected` **每次真实会话丢失恰触发一次**，避免上层 churn 计数虚高。
- **auth_type=1 超窗重建**：华为签名时间戳有 ±30 分钟容差；仅当**断开且距生成 ≥30 分钟**时由监督线程销毁并按新时间戳重建实例（`auth_type=0` 凭据自洽，永不重建）。

**被否决的方案**：把平台分支写进 `mqtt_client`（如 `if (huawei)`）——破坏"call site 零分支"，改为平台层组装连接参数；用分桶式 `now/1800 != built_ts/1800` 判超窗——跨桶边界处会 2 秒即误判重建，改用「已流逝时间 ≥1800s」。

**验证方式**：`tests/test_mqtt_client.c`（CONNACK 回调调度 / 主题构造 / 重建窗口边界 / 断连去重）；真机 8883 握手与重连（真机项）。

**后续**：无。

### 4. 断网续传与本地存储（`storage.c/h`）

**职责**：断网期间把数据落到本地 SQLite 队列，恢复后按原采样时间补发，**且不丢数据**。

**关键设计与理由**：

- **逐条发布、成功才删除**：旧实现"循环发完无条件删除"会把发布失败的条目也删掉，导致永久丢数据；现改为**仅删除确认发布成功（`E_OK`）的条目**，失败条目保留、下轮重试。
- **原始采样时间一并入库**：重放时 `event_time` 取记录自带的 `timestamp_ms`（原采样时刻），故平台时间轴反映真实采样时刻而非接收时刻（续传时间轴 <1s 的基础）。
- **固定列 + 逐列迁移**：字段扩展走 `ALTER TABLE` 加列（复用既有迁移模板），不引入通用迁移框架。
- **`source`/`source_id` 同行存储**：重放时仍能按来源路由到正确的子设备主题。

**被否决的方案**：内存队列（掉电即丢）；发布后无条件删除（丢失败数据）。

**验证方式**：`tests/test_storage.c`（队列读写回环、迁移、失败保留）。

**后续**：无。

### 5. OTA 远程升级（`ota.c/h`）

**职责**：通过命令下发触发固件升级，安全地切换到新版本，失败可回滚。

**关键设计与理由**：

- **A/B 双槽 + 原子切换**：升级写入备用槽，`current_slot` 原子写（tmp + fsync + rename + 目录 fsync），掉电不丢切换状态；升级失败不影响当前运行版本。
- **签名验签 fail-closed**：公钥未配置 → **直接拒绝升级指令**（绝不降级为只验 checksum）；`.sig` 缺失/签名不匹配 → `FAILED` 且绝不切槽。checksum 只做快速失败，签名才是防伪造的根。
- **HTTPS 下载 + 主机名校验**：`SSL_VERIFY_PEER` + CA 锚点 + SNI + 主机名匹配；CA 找不到即拒绝。
- **独立 OTA 线程（500ms 轮询）**：下载/验签/安装这类分钟级阻塞**不再卡住上报线程**（曾经把状态机挂在上报循环里，导致断网补发/心跳被拖死）。
- **启动确认 + 自动回滚**：新版本稳定运行 `boot_confirm_sec` 后清零试用计数；试用期内反复失败 → 自动切回旧槽。
- **重启经 `exit(42)` + systemd `RestartForceExitStatus=42`**：由 systemd 拉起目标槽位，进程不自杀式 `reboot`。

**被否决的方案**：明文 HTTP 下载 + 仅 checksum（防不住"指令+固件同时被换"）；把 OTA 状态机挂在上报循环（阻塞上报）。

**验证方式**：`tests/test_ota.c`（签名验签、解析、状态机）；真机 A/B 端到端（真机项）。

**后续**：无。

### 6. 平台抽象层（`platform.c/h` 分发器 + `platform_local.c`）

**职责**：把「平台差异（连接参数组装 / 下行路由 / 上报路径）」收敛到一张 `platform_ops` 函数指针表之后，让 `mqtt_client`/`main` 等调用点**零分支**。

**关键设计与理由**：

- **`struct platform_ops`（9 个函数指针）**：`connect_params / on_connected / on_disconnected / on_message / publish_status / publish_data / publish_alert / tick / shutdown`。新增平台只加一个 `.c` + 一张表，不动传输层。
- **`platform_select()` 在**任何线程创建之前**写定 `g_active`**：此后 `g_active` 只读，无需原子/锁。
- **local 路径与 v1.2.11 逐字节等价**：local 是永久保留的回归基线，切平台只改配置不改代码（`platform = local | huawei`）。
- **下行消息唯一路由**：`mqtt_client.on_message` 不判 topic，全量转发 `platform_dispatch_message`；`ota/cmd` 路由**仅**在 `platform_local.on_message` 内——任一模式有且只有一条下行路由，杜绝双处理。
- **装配期决策**：`platform = huawei` 时校验凭据（缺则回落 local 保运行），凭据合法则装配 huawei ops；**子设备注册表 0 条不回落**（纯网关是合法模式，仅醒目 WARN）。

**被否决的方案**：在 `mqtt_client`/`main` 里写平台分支——平台差异泄漏、每加一个平台要改多处。

**验证方式**：`tests/test_platform_local.c`（connect_params 组装 / select 装配 / 唯一路由 seam）。

**后续**：无（新增平台即加一个 ops 实现）。

### 7. 线程模型与生命周期（`main.c`）

**职责**：编排所有线程的创建、运行、退出与资源释放。

**关键设计与理由**：

- **单进程多线程 + `g_running` 统一旗标**：主循环阻塞在 `pthread_join`，退出时置 `g_running=0`，各工作线程循环自然收敛。
- **线程归属明确**：
  - `modbus_thread`：南向轮询 → `platform_publish_data`（未连则 `storage_save`）。
  - `upload_thread`（5s）：断网续传重放 + `platform_tick`（网关属性周期上报、子设备离线检测、注册退避）。
  - `ota_thread`（500ms）：驱动 OTA 状态机。
  - `http_thread`：本地 Dashboard。
  - libmosquitto **网络线程**：`on_connected`/`on_message`/`on_disconnected`（命令解析与同步回执在此完成）。
  - **监督线程**（仅 huawei + `auth_type=1`）：10s 周期判超窗重建。
- **优雅退出顺序**：置 `g_running=0` → join 工作线程 → 发 `offline` 状态（best-effort）→ 短延时给网络线程 → `mqtt_close` → 依次关闭各子系统。
- **初始化早于线程**：配置加载、平台装配（含子设备注册表加载）、存储初始化均在**创建任何线程之前**完成，保证运行时只读、无锁。

**被否决的方案**：late-load（线程起来后再加载注册表）——与采样线程竞态；多进程化——单板场景无收益、状态共享复杂。

**验证方式**：`tests/t02_e2e_broker.c`（本机 broker 端到端）；真机守护进程与重启（真机项）。

**后续**：无。

### 8. 待开发：视觉 AI 模型

**职责**：在网关上叠加一路**视觉识别**能力（如作物/病虫害/植株状态），作为"边缘 AI"的差异化能力。

**关键设计与理由**：

## 模块三 · 云端

> 云端 = 华为云 IoTDA 接入的全部实现 + 云侧配置 + 真机验证。

### 1. 华为接入纯函数层（`platform_huawei.c/h`）

**职责**：把华为云 IoTDA 的协议细节（鉴权、主题、payload）做成**无全局状态、无 I/O、可单测**的纯函数集合。

**关键设计与理由**：

- **鉴权三元组现算**：`client_id = {device_id}_0_{auth_type}_{yyyyMMddHH}`（UTC，`gmtime_r`，**严禁 localtime**）；`password = HMAC-SHA256(以时间戳为密钥, 对 secret 加密)`，输出**固定 64 位小写 hex**；`username = device_id`。
- **`auth_type` 语义**：`0` = 不校验时间戳（凭据自洽，推荐默认，规避时钟漂移）；`1` = 校验（服务端有 ±30 分钟时间窗容差）。
- **force_tls 恒 1、use_will 恒 0**：华为 8883 强制 TLS，平台不支持遗嘱。
- **JSON 注入防护**：所有 payload 由受控 builder 构造，字段遍历走字段描述表；**截断统一返回 `E_IO` 并拒绝发布**（绝不发半截 JSON）。
- **哨兵省略（方案 A）**：值 == `SENSOR_VALUE_INVALID` 的字段**整体不写入** properties，依赖华为设备影子按属性合并；三字段全空则**不发空对象**（返回特征码，调用方跳过）。
- **命令参数全字符串硬约束**：网关侧 JSON 提取器是严格子集（只认带引号字符串），故云侧命令 `paras` 必须全定义为字符串型。

**被否决的方案**：引入华为 SDK/通用 JSON 库（破坏零侵入、增加依赖）；自造鉴权测试向量（必须取官方示例/控制台生成工具）。

**验证方式**：`tests/test_platform_huawei.c`（client_id 拼装、HMAC 向量、keepalive 钳制、payload 截断与哨兵 mask）。

**后续**：无。

### 2. 子设备管理实现（`platform_huawei_subdev.c`）

**职责**：华为侧的 9 成员 `platform_ops` 装配 + 子设备注册/上下线/批量上报/退避重试。

**关键设计与理由**：

- **运行期状态与注册表索引对齐、无锁**：`struct subdev_runtime` 与注册表条目按索引对齐；跨线程标量 `registered`/`online`/`last_seen_ms`/`next_reg_ms` 用 `_Atomic`，`reg_fail_cnt`/`empty_skip_cnt` 仅上传线程访问。**只读数组 + 原子标量 = 全程无互斥锁**（网络线程禁止锁内 I/O）。
- **时钟域纪律**：`last_seen_ms`/`next_reg_ms` 一律 `CLOCK_MONOTONIC` 毫秒，**禁止**复用 wall-clock 的 `timestamp_ms`（NTP 步进会破坏离线判定）。
- **注册退避**：`next_reg_ms` 单调退避 `min(30s × n, 300s)`，注册失败有日志、不刷屏。
- **批量上报返回契约**：`E_OK` = 该样本已完全处置（成功发布 **或** 永久不可路由而丢弃）；非 `E_OK` = 瞬态可重试。据此断网续传"成功才删除"逻辑零改动即正确处理"子设备已不存在"的陈旧记录。
- **P1-16 部署链修复**：`subdevices.conf` 默认路径改**绝对** `/etc/embmqttnode/subdevices.conf`，并补齐 `dist` 打包与 `install` 安装（否则板上静默失效为"纯网关"）。

**被否决的方案**：注册表 0 条回落 local（会把设备切到错误 broker，远比"无子设备"严重）；运行期加互斥锁（与"网络线程锁内零 I/O"冲突）。

**验证方式**：`tests/test_platform_huawei_subdev.c`（count/at、init 对齐、publish_data 返回契约、status/alert、tick 退避、select 装配）。

**后续**：无。

### 3. 命令闭环（`platform_huawei_cmd.c`）

**职责**：接收平台下行命令、解析执行、同步回执；OTA 桥接与终态事件 shim；churn 检测与超窗重连。

**关键设计与理由**：

- **命令解析矩阵**：`command_name` 决定路由；`ota_upgrade` 的 `paras{cmd,version,url,checksum}` 逐字段 `json_get_string` 校验（缺 / 空 / 非字符串 / 超长各有处置）。**畸形 JSON 绝不崩溃**（严格子集 + 本地 NUL 缓冲）。
- **回执码语义（0/1/2）**：`0` = 受理成功（`upgrade accepted` / `rebooting`）；`1` = 解析失败或 busy 或拒绝；`2` = 未知命令。判定顺序固化，逐条可测。
- **回执主题拼接**：`HW_TOPIC_COMMANDS_RESPONSE` 基址 + `/request_id={rid}`（两步拼接 + 截断拒绝）；`rid` 提取失败则**不处理不回执**（视为畸形）。回执 QoS1、网络线程内同步。
- **OTA 桥接（`ota.c` 零改动）**：把华为 `paras` **重建为扁平旧 schema** 再喂 `ota_handle_message`；受理/busy 用既有公开 API `ota_state_string()` 做**前置 busy + 调用后立即后置复核**判定（仍 idle=被拒，否则受理）。**先受理、后回执**。
- **OTA 终态 shim**：`main` 注入分发器回调，华为模式下把 OTA 状态转 `ota_status` 物模型事件（`event_type="ota_status"`）发 `events/report`；与命令回执靠**主题/触发源正交**天然不重复。
- **reboot 顺序**：**先回执后停机**（`g_running=0`），不在网络线程内延时；由 systemd `Restart=always` 拉起完成配置生效。
- **churn 检测**：`on_disconnected` 记录断连间隔，30s 内累计 ≥3 次打 WARN（flapping），仅日志不改协议行为。

**被否决的方案**：改 `ota.c` 加返回值/回调（扩大改动面，违背"ota.c 零改动"）；透传华为原始 payload（依赖嵌套键巧合、脆弱）；先停机后回执（进程退出后回执丢失）。

**验证方式**：`tests/test_platform_huawei_cmd.c`（解析矩阵 / 回执码与主题拼接 / ota_status 事件 schema / shim 映射 / reboot 顺序；`--wrap=ota_handle_message` 注入桩）。

**后续**：真机收口（见模块三 · 5）。

**关键设计与理由**：

- **产品与物模型**：1 个网关产品（MQTT，设备类型=网关）+ 各子设备型号；定义网关属性、子设备 service/属性；**命令定义**（OTA 升级、重启——命令名与参数须与网关实现对齐后冻结，**`paras` 全字符串型**）；**告警事件类型**（字段名与 `hw_build_event_alert` schema 单点对齐）。

**验证方式**：控制台设备树 + 属性实时 + 命令回执 + 事件可见（真机项）。

## 模块四 · 辅助模块（工程支撑）

### 1. 配置系统（`config.c/h`）

**职责**：解析 INI 风格 `node.conf`，提供带校验的运行参数。

**关键设计与理由**：

- **INI 解析**：`key = value`，`#`/`;` 注释，`[段]` 跳过；行/值缓冲按需扩容（长字段不静默截断）。
- **校验与钳制（fail-closed）**：范围非法即校正或拒绝（如 keepalive 钳制 30..1200、Modbus 参数范围校验、命令 `field` 名加载期查表校验）。
- **未知键静默忽略**：保证向后兼容（旧配置不因新字段报错）。
- **敏感字段打码**：`config_dump` 中 secret 打码为 `(configured)`，永不打日志。

**被否决的方案**：引入 libconfig/JSON 配置文件（过度依赖）；无校验直接信任（现场误配难排查）。

**验证方式**：`tests/test_modbus_config.c`（解析与校验）。

### 2. 设备身份（`mac_addr.c` + client_id 自动生成）

**职责**：生成稳定、唯一的设备标识。

**关键设计与理由**：

- **读网卡 MAC（`eth0`/`wlan0`）**：`client_id = "emb-node-" + MAC 后 6 位`——同一块板重启后身份稳定。
- **首次启动写入配置**：后续保持不变，避免身份漂移导致云端设备重复注册。
- **本地路径的遗嘱/状态主题**基于该 `client_id`。

**被否决的方案**：随机 UUID 每次启动生成（云端设备爆炸）；纯主机名（多台同名冲突）。

**验证方式**：`tests/test_mac_addr.c`。

### 3. 本地 Web Dashboard（`http_server.c/h`）

**职责**：板上提供一个只读看板 + 受保护的重启接口。

**关键设计与理由**：

- **REST API + 内嵌单页**：`/api/status`、`/api/data/latest`、`/api/data/history` 等，前端页面内嵌于 C 字符串，无外部依赖。
- **常量时间 token 比较**：`/api/reboot` 认证用常量时间比较，**默认 fail-closed**（未配 token 一律 403），并有请求限速。
- **增量拼接越界守卫**：JSON 逐段拼接带长度守卫，杜绝越界；接收侧有 `SO_RCVTIMEO`/`SO_SNDTIMEO` 超时。
- **字段序查表**：Dashboard JSON 由字段描述表遍历生成（新增字段不遗漏 C 侧）。

**被否决的方案**：Dashboard 无鉴权即可重启（P1 安全缺陷）；引入第三方 HTTP 框架/前端构建链（板上过重）。

**验证方式**：`tests/test_mqtt_client.c`（含 `http_consttime_token_equal` 用例）。

### 4. 构建与部署（工程基本）

**职责**：交叉编译、打包、安装、服务托管。

**要点（简述）**：

- **Makefile 交叉编译**：`make CROSS_COMPILE=aarch64-linux-gnu-`；`make -C tests` 跑单测；`make dist` 出发布包；`make install DESTDIR=...` 安装。
- **systemd + A/B launcher**：`embmqttnode.service`（`Restart=always`、`WorkingDirectory=/var/lib/embmqttnode`、`ReadWritePaths=/etc/embmqttnode /var/lib/embmqttnode`）；`embmqttnode-launcher` 读 `current_slot` 启动对应槽位，`RestartForceExitStatus=42` 支持 OTA 后切换。
- **`BUILD_WITH_MODBUS=0/1` 双配置零警告**：有/无 Modbus 硬件的环境都能干净构建。
- **部署件**：二进制到 `/var/lib/embmqttnode/slot_a|b/`，`node.conf` 与 `subdevices.conf` 到 `/etc/embmqttnode/`。

**验证方式**：双配置构建零警告；`make test` 全绿；`make dist` / `install` 产物核对。

## 演进史（四段，只讲"为什么改"）

**一、单传感器节点（v0.x）**
最初是一个 I²C 环境监测节点（BMP280/SHT30 采集 → MQTT 上报本地 broker，SQLite 断网缓存、LED 指示、守护进程化）。**为什么改**：单点采集只能体现"会用 I²C 和 MQTT"，无法体现"多协议网关"这一工业场景的核心能力，也无法承载"设备不丢数据、能远程升级"的运维故事。

**二、边缘网关（v1.x）**
引入 Modbus 主站（RTU/TCP 采集存量设备）、规则引擎 + GPIO 告警、A/B 分区 OTA、本地 Web Dashboard、MQTT over TLS 与遗嘱消息。**为什么改**：要把项目从"数据能上云"升级为"设备可运维、可安全升级、可多协议接入"的工业边缘网关；同时做过一版端侧异常检测（Z-score + Isolation Forest）作为"边缘 AI"的探路。

**三、华为云接入（v1.3.0）**
新增平台抽象层（`platform_ops` 函数指针表 + local/huawei 双实现），打通华为云 IoTDA：鉴权三元组、网关/子设备属性、命令闭环、告警物模型事件、断网续传带原始时间、TLS 强制与超窗重连。**为什么改**：私有 broker 缺"主流云平台接入"这一硬指标；且用平台抽象层把协议差异隔离，使"切云平台只改配置不改代码"、local 路径成为永久回归基线。

**四、纯网关化（v1.4.0 / v1.5.0 → v1.5.1）**
**移除**板载 I²C 采集（`sensor.c`/`sample_thread`）、GPIO 执行层（`gpio_hal`）、规则引擎与异常检测引擎（`rule_engine`/`anomaly_engine`/`iforest`）。**为什么改**：在"网关"定位下，本地采集与 GPIO 执行属职责错位——采集本就该由**子设备**（STM32，见模块一）承担，执行与离线兜底也该下沉到子设备；本地 ML 则并入后续**视觉 AI** 路线。网关回归它最该做的事：**协议转换 + 云端接入 + 数据可靠**，从而更小、更稳、更好维护。**保留**并继续使用 `struct alert_event` / `platform_publish_alert`（local/huawei 两实现）/ `hw_publish_alert` + `events/report`，供后续"浇水后复测告警"等复用；保留 `sensor_fields`、`SOURCE_LOCAL`（旧库回放兼容）、断网续传、A/B OTA。

## 附录：原始设计裁定摘录要点

> 摘自 PRD（11）与三份设计裁定（12/13/14）中仍需长期遵守的结论。

**鉴权与连接（华为 IoTDA）**

- `client_id = {device_id}_0_{auth_type}_{UTC yyyyMMddHH}`（`gmtime_r`，严禁 localtime；`auth_type=0` 亦取真实 UTC 时间）。
- `password = HMAC-SHA256(以时间戳为密钥, 对 secret 加密)`，固定 64 位小写 hex（官方 p472/p523 依据）。
- `auth_type=1` 服务端 ±30 分钟容差；仅"断开且距生成 ≥30 分钟"才重建实例（否决分桶式判定）。

**子设备与上报**

- 平台=local|huawei 由配置切换，local 与 v1.2.11 逐字节等价（永久回归基线）。
- 子设备映射表驱动、数据源无关；`subdevices.conf` fail-closed 校验、`device_id` 与源键全表唯一。
- 批量上报采用**方案 A（哨兵字段省略 + 逐条碎片化）**，依赖华为设备影子按属性合并（否决按从站聚合）。
- 哨兵统一 `SENSOR_VALUE_INVALID (-999.0)`；local 不 mask，mask 仅在华为 builder。
- `subdevices.conf` 默认绝对路径 `/etc/embmqttnode/subdevices.conf`，`dist`/`install` 同批打包（P1-16）。
- 注册表 0 条**不回落** local（纯网关为合法模式，仅醒目 WARN）。

**数据字段**

- 字段映射单一事实源 `SENSOR_FIELDS[]`（表序 = 序列化序，冻结不变式）；新增字段固定 4 步、消费侧零改动。
- **明确不采用**动态 key-value / EAV / JSON blob。

**命令与 OTA**

- 命令 `paras` 必须**全字符串型**（网关 JSON 提取器为严格子集）。
- 回执码：`0` 受理 / `1` 解析失败或 busy / `2` 未知命令；命令结果 100% 回执。
- **`ota.c` 零改动**：OTA 经命令桥接复用（扁平旧 schema），受理判定用 `ota_state_string()` 前后观测。
- OTA 终态经 `ota_status` 物模型事件补报；reboot **先回执后停机**。

**可靠性**

- 断网续传逐条发布、**成功才删除**；重放沿用原始 `timestamp_ms`（时间轴 <1s）。
- 断连去重：`platform_on_disconnected` 每次真实会话丢失恰一次（避免 churn 虚高）。
- OTA 签名 fail-closed：公钥未配置即拒绝，绝不降级为 checksum-only。

**安全**

- 华为模式 TLS 由 `force_tls` 强制驱动，不再依赖用户配 `tls_enabled`。
- Dashboard 重启接口常量时间 token 比较 + 默认 fail-closed + 限速。
- `secret` 永不打日志（`config_dump` 打码）。
